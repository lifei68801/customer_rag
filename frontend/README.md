# 客服智能问答 Demo（前端）

基于 Agent 推理核心 + GraphRAG + 检索增强的企业客服问答系统体验 Demo。视觉设计详见
[`DESIGN.md`](./DESIGN.md)（neo-brutalism 风格，实测自 raft.build/zh-cn，米白背景+硬边框+
硬投影，不是深色主题）。

## 启动前置条件

1. **后端环境配置**：仓库根目录的 `.env` 需要配好真实的 `CUSTOMER_RAG_EMBEDDING_*`、`CUSTOMER_RAG_LLM_*`（摄取和问答都要真实调用这些 API），以及可用的 Milvus（`CUSTOMER_RAG_MILVUS_URI`）。如果要体验 GraphRAG 术语强制注入能力，还需要配置好 Neo4j（`CUSTOMER_RAG_NEO4J_*`）。
2. **摄取示例语料**（必须先做这一步，否则打开 demo 问什么都会得到"未找到确切答案，已转人工"的兜底话术）：

   ```bash
   .venv/Scripts/python.exe -m app.ingestion.main --dir docs/demo-data --tenant-id demo --build-graph
   ```

   `--tenant-id demo` 必须和这个前端硬编码的租户一致（见下方"已知限制"）。
3. **启动后端**（必须监听 8000 端口，`vite.config.ts` 的开发代理硬编码了这个端口）：

   ```bash
   .venv/Scripts/python.exe -m uvicorn app.main:app --port 8000
   ```

## 启动前端

```bash
cd frontend
npm install   # 首次运行需要
npm run dev
```

打开浏览器访问 `http://localhost:5173`（**必须用 `localhost`，不要用局域网 IP 访问**——聊天界面用了 `crypto.randomUUID()` 生成会话 ID，这个 API 只在浏览器认定的安全上下文里可用，`http://localhost` 是安全上下文，但 `http://192.168.x.x` 这类局域网 IP 不是，会导致页面加载就报错白屏）。

## 已知限制

- 前台问答页的租户固定写死为 `"demo"`（`frontend/src/hooks/useAgentChat.ts` 里的 `TENANT_ID` 常量），没有切换入口——摄取语料时也必须用同一个 `--tenant-id demo`，否则前端检索不到任何内容。
- 管理后台（`/admin/*`）有租户切换下拉框（侧边栏底部，切换后"本体 Schema 管理"/"文档管理"/"数据填充"这三个导航项都会按新租户重新拉数据，本体 Schema 管理页里的"产品线" tab 除外——它是全局配置，不区分租户），但下拉选项目前只硬编码了 `demo` 一项：后端没有"列出所有租户"的接口，所以还没法真正切到别的租户。
- 只支持文字问答，不支持语音输入/输出。
- 只有浅色主题（米白+黑边框），没有深色模式切换。
- 不引入自动化测试框架，`npm run typecheck`/`npm run build` 是主要的正确性验证手段。

## 人工验收清单

功能实现完成后，建议在浏览器里逐项确认：

1. 打开 `http://localhost:5173`，Hero 区标题/副标题正常显示，米白背景+黑色硬边框+糖果色
   强调色符合预期（黄色导航栏、粉色主按钮）。
2. 输入"网关超时示例是什么意思？"，观察回答是否有逐句流式出现的效果（不是一次性蹦出全部文字）。
3. 回答下方出现来源引用标签，格式类似"📄 docs\demo-data\faq-error-e502.md#0"（含目录前缀、chunk 序号，这是正常格式，不是精简过的纯文件名）。
4. 连续追问一个指代不明的问题（如先问"E502 怎么处理"，再问"那这个问题会不会丢数据"），观察多轮对话是否连贯（依赖后端记忆/指代消解能力）。
5. 关掉后端进程后再发一条消息，确认界面能看到"连接后端失败"的错误提示（追加显示，不会抹掉已经流式显示出来的部分回答），而不是卡死无响应。
6. 用浏览器开发者工具的移动端模拟视图，确认页面在窄屏下没有明显的布局错乱（没有专门做响应式适配，这里只是留意有没有严重问题）。

### 管理后台

前置条件：仓库根目录 `.env` 里配好 `CUSTOMER_RAG_ADMIN_TOKEN=<任意随机串>`（留空的话所有登录
一律 401，第 8 步会永远失败），并重启后端进程让新配置生效。

7. 前台导航栏最右侧点击"⚙️ 管理后台"，站内跳转到 `/admin/login`（不开新标签页），未登录状态下
   直接访问 `http://localhost:5173/admin/documents` 也会被重定向到 `/admin/login`。
8. **登录（错误 token）**：随便输一串错的 token 点登录，页面显示"管理员 token 不正确"之类的
   错误提示且停留在登录页；同时后端控制台应打印一条 `管理员登录失败` 的 WARNING（不含 token 值）。
9. **登录（正确 token）**：输入 `.env` 里的 `CUSTOMER_RAG_ADMIN_TOKEN`，登录成功后跳到
   `/admin/documents`，左侧看到"本体 Schema 管理"/"文档管理"/"数据填充"三个导航项、底部有租户
   下拉框和登出按钮。其中"数据填充"下面还有三个子 tab："实体列表"（原术语库管理）、"结构化数据
   加工"（原 ETL 跑批）、"非结构化数据加工"（原知识图谱审核）。
10. **上传（不建图）**：选一个 `.md` 文件，**不勾**"同时构建知识图谱"，点"上传文档"。先在
    "处理中的任务"里看到这个文件，几秒后（列表每 3 秒自动轮询）它消失并出现在"已摄取文档"里，
    带上 chunk 数量。再试着上传一个 `.exe` 或 `.txt`，应当立刻报"不支持的文件类型"，不进任务列表。
11. **上传（建图）前置条件**：在做这一步之前，先确认要用的租户已经在"本体 Schema 管理"页把
    本体 schema 确认（confirm）过——图谱抽取只在租户本体已确认的状态下才会执行，没确认过的
    租户上传文档会正常摄取/向量化，但不会产生任何候选（既不写入 Neo4j 也不进待审核队列），
    界面上也不会有报错提示，容易被误当成"抽取失败"。用一个全新/还没确认过本体的租户走这个
    验收步骤，会在第 14 步看到"待审核"列表始终为空，此时应先去确认本体，而不是排查 bug。
12. **上传（建图）**：勾上"同时构建知识图谱"再传一个内容里含术语表实体的 `.md`，同样等它进入
    "已摄取文档"。这次会额外走 LLM 关系抽取，耗时更久；两侧实体名对齐术语表、但抽取出的关系
    类型或 (subject 类型, 关系类型, object 类型) 组合不在该租户已确认的本体范围内的候选，会
    降级进第 14 步的待审核列表（原因显示为 `not_in_confirmed_ontology`），不会直接写图谱——
    只有两侧实体名对齐**且**关系类型/类型组合都在已确认本体范围内的候选，才会直接写进 Neo4j、
    不出现在待审核里。
13. **删除文档**：在"已摄取文档"里点任意一条的"删除"，该条从列表消失；确认磁盘上
    `data/uploads/demo/` 对应的那个 `<uuid>_<原文件名>` 文件也不见了（不是只清了索引）。
14. **图谱审核 - 批准**：进"数据填充"页的"非结构化数据加工" tab（原"知识图谱审核"页），
    "待审核" tab 里任取一条候选，确认 subject/object 两个输入框已经预填了后端给的建议标准名
    （`suggested_*` 为空时输入框留空）；把任一输入框清空，"批准"按钮变灰不可点；两个都填上后点
    "批准"，该条从"待审核"消失，切到"历史记录" tab 能看到它标着"已批准"和处理时间。
15. **图谱审核 - 驳回**：另取一条点"驳回"，同样从"待审核"消失，"历史记录"里标着"已驳回"。
16. **租户切换真的会重新拉数据**：先给另一个租户摄取一点语料
    （`.venv/Scripts/python.exe -m app.ingestion.main --dir docs/demo-data --tenant-id other`），
    并临时把 `frontend/src/admin/TenantSwitcher.tsx` 的下拉框加上 `<option value="other">other</option>`；
    然后在"文档管理"页切换下拉框，确认标题里的"（租户：xxx）"跟着变，且**文档列表内容整体换成
    新租户的**（不是原地不动）；切到"数据填充"页的"非结构化数据加工" tab，待审核列表同样按新
    租户重新拉取。验证完把临时加的 `<option>` 去掉。
