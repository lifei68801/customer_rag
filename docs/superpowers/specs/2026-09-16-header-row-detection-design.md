# 表头行自动探测：为什么按填充密度做不成，以及下一步该怎么做

**状态**：调研结论 + 待实现设计
**日期**：2026-09-16
**前情**：`docs/superpowers/plans/2026-09-15-source-parse-options.md` 的 Task 6。该任务经过 4 轮修复后**从计划中移除**，代码未接线即删除（见下）。

## 为什么记这一篇

表头行探测在"数据源解析选项"计划里做了四轮，每一轮修好一处都在别处冒出新问题。最后的结论不是"没做完"，而是**这条技术路线被定量证明走不通**。这个结论比代码值钱——不写下来，下一个人会照着同样的直觉再做一遍。

## 要解决的问题

MUJI 的 SKU 主数据表（`CN_001_SKU_MASTER_121.xls`，`Master` 工作表，113 列）表头不在第一行：

| 行 | 非空格子数 | 是什么 |
|---|---|---|
| 1 | 5 | 合并标题带 |
| 2 | 8 | 几乎全空 |
| 3 | 107 | 英文列名 |
| 4 | 92 | 日文列名 |
| 5 | 105 | Character Limit 说明行 |
| 6 | 108 | **真表头**（系统代码列名） |
| 7 起 | 72 | 数据 |

用户不该每次都自己数这是第几行。

## 走过的四条路，以及各自死在哪

| 规则 | 死因 |
|---|---|
| 非空数 × 后瞻平均填充率，取最高分 | 真实 MUJI 选中第 3 行——表头堆上层"往下还能看到别的表头层"而被拉高分，真表头往下看到的是稀疏数据反而吃亏 |
| 从上往下第一个"自身非空且后瞻稳定"的行 | 四类常见形状倒退：表头上方一行标题、表头前的信头块、数据本身参差、窄表缺一格 |
| 找稳定数据块 + 前一行提拔一格 | 用候选行自身长度当密度分母；SheetJS 会截掉行尾空单元格，密度算出 >1 |
| 统一分母 = 扫描区最大行宽 | 一个远端孤立单元格就能撑大分母、压扁全表密度信号（MUJI 6→3，更远 6→1）；扫描区外的行也能污染；`Math.max(...rows)` 在约 13 万行时抛 `RangeError` |
| 改按非空**计数**、彻底不用分母 | 消除了上面整类分母问题，但暴露出下面这个**原理性**障碍 |

## 原理性结论：固定比例分不开"多层表头堆"和"参差数据"

最后一版的判据是"窗口内非空计数的落差 ≤ 比例 × 窗口内最大计数"。把两种必须区分的形状代进去：

| 形状 | 落差 ÷ 最大计数 | 规则必须满足 |
|---|---|---|
| MUJI 表头堆（真实数据） | 36 / 108 = **0.333** | 比例 **< 0.333** 才能拒绝它 |
| 普通表，10 列，数据 7~10 格波动 | 3 / 10 = **0.30** | 比例 **≥ 0.30** 才能接受它 |
| 普通表，10 列，数据 6~10 格波动 | 4 / 10 = **0.40** | 比例 **≥ 0.40**，此时 MUJI 必然被判错 |

可用区间只剩 0.30~0.333 这条缝，数据稍微再参差一点就重叠。**不存在能同时满足两者的固定比例。**

实测佐证：取比例 0.2，构造"表头满格 10、数据 7~10 格波动"的普通表，用带种子的伪随机跑 200 次，**99 次判错**（多数落在数据区深处）；把波动收窄到 8~10 格，200 次 0 错。也就是说最常见的表形状（表头在第 1 行、有若干可选字段）在中等波动下约一半概率给出错误建议。

## 为什么"只是个建议"不足以兜底

前后端**都**用同一份解析选项，所以猜错的表头行**不会被跑批前的列名对账拦住**（两边一致地错）。用户如果没注意到预填值，数据会以"成功"的状态导入成垃圾。对表头本来就在第 1 行的普通表，这比不做探测更差——是回归，不是"不够好"。

## 因此：本计划不做自动探测

解析选项已经随映射持久化（`sources:` 段），**每种文件形状只需手填一次表头行，之后重导都沿用**。这让"不做探测"的代价远低于它看起来的样子。表格导入的解析设置面板给出前若干行的原始预览（带行号、高亮当前表头行），用户自己挑。

`detectHeaderRow.ts` 及其测试在未接线的状态下删除——留着一个"没人用、但一半情况会猜错"的函数，下一个人会当它能用。四轮的发现保存在这一篇里。

## 下一步该怎么做：看"像不像数据"，而不是"有多满"

密度只回答"这一行填了多少格"，而表头和数据的真正区别是**内容形态**：

- 数据行含有数字、日期、编码（MUJI 第 7 行起有 JAN 码 `4934761229522`、价格 `998`）
- 表头行是名字：非数字、较短、行内大多互不重复

方向：**从上往下找第一个"像数据"的行，表头 = 它上面紧挨着的非空行。**

代进已知形状：

| 形状 | 结果 |
|---|---|
| MUJI | 第 7 行像数据 → 表头 = 第 6 行 ✓ |
| 普通表、数据参差 | 第 2 行像数据 → 表头 = 第 1 行 ✓（**与填充波动无关**，上一条路线正是死在这里）|
| 表头上方一行标题 | 第 3 行像数据 → 表头 = 第 2 行 ✓ |
| 表头前一叠信头 | 第 7 行像数据 → 表头 = 第 6 行 ✓ |
| 窄表缺一格 | 第 2 行像数据 → 表头 = 第 1 行 ✓ |

**尚未解决、必须在实现前想清楚的**：

1. **纯文本数据表**（如"客户名 / 城市"两列，数据里没有任何数字或日期）——"像数据"的信号不成立，需要兜底规则。候选：看列内取值是否重复（数据列会重复，表头行不会）、或直接回退第 1 行。
2. **判据要用多份真实文件评估**，不能只拿 MUJI 一张表调。上一条路线的每一次翻车都是"在手上这张表能过"。
3. 探测仍然**只提议、不自动生效**，且界面要让偏离一眼可见。

这三条决定了它值得一份独立的 spec 和自己的实现计划，而不是塞回解析选项那个计划里。
